# 내 카드

React + Vite로 만든 개인용 모바일 PWA입니다. 서버·계정·DB 없이 localStorage에 저장합니다.

## 실행

```sh
npm install
npm run dev
```

## 정적 빌드 및 확인

```sh
npm run build
npm run preview
npm test
```

`dist/` 전체를 HTTPS 정적 호스팅에 올리면 스마트폰에서 설치할 수 있습니다. iPhone은 Safari 공유 → 홈 화면에 추가, Android는 브라우저 메뉴 → 앱 설치를 사용합니다. localhost는 PWA 검증이 가능하지만 스마트폰의 일반 HTTP LAN 주소에서는 설치와 서비스 워커가 제한됩니다.

초기 목표는 카드당 30만원이며 실제 카드 조건이 아닙니다. 초기 실적은 0원, 자동결제와 즐겨찾기는 비어 있습니다. **카드 상세 → 상품 확인·변경**에서 정확한 상품·Edition·PACK을 연결하세요. 삼성 패키지도 카드사 앱의 현재 적용값과 맞춰주세요. **전월실적** 버튼에서 카드사 인정 금액을 기록할 수 있습니다.

공식 혜택 38개를 상품 5개 유형으로 분리했습니다. 삼성 taptap O, 네이버 현대카드 원본(Edition1), KB ALL(구 WE:SH All), NH올원더풀 할인/적립 PACK을 포함합니다. 네이버 Edition2·3은 미검토 상태이며 임의 적용하지 않습니다. KB ALL YOU NEED 문구만으로 상품을 확정하지 않고 사용자가 연결해야 합니다. 기존 요약·추천 규칙은 ‘나의 참고’로 보관하며 금액 계산은 공식 데이터만 사용합니다.

## 구조

- `src/data/cards.js`: 초기 카드 데이터
- `src/utils/finance.js`: 추천 및 실적 계산
- `src/utils/storage.js`: 백업 검증, 월 기록 이월
- `src/hooks/useCardStore.js`: localStorage 저장 및 월 변경 확인
- `src/components/`: 카드와 접근 가능한 바텀시트
- `src/components/OfficialBenefits.jsx`: 공식 혜택 상세, 상품 연결, 금액 비교
- `src/data/official-benefits.json`: 검증된 정규화 공식 혜택 (앱에 번들, 오프라인 가능)
- `src/data/benefit-status.json`: 공식 출처별 갱신 상태 (사용자 기록과 분리)
- `src/utils/benefits.js`: 전월 조건·비율·정액·한도·Edition·비교 계산
- `scripts/benefits/`: 공식 출처 어댑터, 검토 원본, 안전한 갱신
- `.github/workflows/benefits.yml`: 매주 월요일 07:20 KST 공식 원문 확인
- `public/manifest.json`, `public/sw.js`: 설치 및 오프라인 지원
- `scripts/precache.js`: 빌드 결과를 서비스 워커 사전 캐시에 추가

실적은 현재까지의 직접 입력 금액입니다. 예상 실적은 실적 포함으로 지정한 자동결제 월 금액을 더한 참고값으로, 이미 입력한 결제와 중복될 수 있습니다. 짧은 달의 29~31일 실제 결제일은 카드사에 따라 달라집니다.

브라우저/기기별로 데이터는 별개입니다. 내 카드 → 데이터 백업에서 JSON을 내려받고 다른 기기에서 복원하세요. 복원 전 검증과 교체 확인을 거칩니다. 저장값이 손상되면 원본을 보존하고 복원을 안내합니다.

## 공식 혜택 갱신

브라우저는 카드사에 요청하지 않습니다. 별도 Node 스크립트가 공식 페이지·PDF를 확인하고 JSON을 생성합니다. 비율 변경을 임의 해석하지 않는 **검토 기반 정규화 + 자동 변경 감지** 방식입니다. 서버·DB·유료 API가 필요하지 않습니다.

```sh
npm run benefits:update  # 공식 원문 확인, 정상 데이터 유지, 상태 갱신
npm test
npm run build            # JSON 검증 후 오프라인 정적 빌드
```

원문이 검토한 내용과 같을 때만 확인일을 갱신합니다. 네트워크 실패·구조 변경·빈 응답은 기존 혜택을 그대로 보존합니다. 원문 내용 변경은 ‘확인 필요’로 표시하고 수치 자동 교체를 중지합니다. 30일이 지나면 ‘정보가 오래됨’이 표시됩니다. 갱신 실패·검토 필요·오래된 정보는 비교 화면에 남지만 추천 대상으로 선정하지 않습니다.

GitHub에 올리면 워크플로가 JSON/상태를 커밋하고 검증된 `dist` 아티팩트를 만듭니다. **현재 원격 저장소·호스팅에 배포하거나 스케줄을 실제 활성화한 것은 아닙니다.** 기존 정적 호스팅의 배포 단계에 연결하거나 아티팩트를 배포해야 앱에 반영됩니다. `GITHUB_TOKEN`의 커밋은 다른 GitHub Actions를 자동 트리거하지 않으므로, Pages 등은 같은 워크플로에 배포 단계를 연결하세요. 오프라인 기기는 새 배포를 받을 때까지 마지막 번들을 사용하며 확인일로 오래됨을 표시합니다.

정규화 필드, 검토 방법, 실패 처리와 계산 제한은 [공식 데이터 운영 문서](docs/official-benefits.md)를 참고하세요.

## 결제 직전 추천

추천 탭은 **매장 → 금액 → 카드 추천 보기** 순서로 사용합니다. 금액을 비우면 할인율·적립률을 기준으로, 금액을 입력하면 한도·정액 할인·전월 인정 실적을 반영한 최대 예상 혜택을 비교합니다. 포인트는 화면에서 P 단위를 유지하고 비교에만 기본 1P=1원으로 환산합니다.

- 매장 사전은 [merchants.js](src/data/merchants.js)에 있습니다. `스벅 감일`, `메가`, `배민`, `네이버 쇼핑`처럼 별칭·부분 검색을 지원하며, 스타벅스·CU·이마트·쿠팡·카카오T 등은 업종으로 보정합니다.
- 최근 검색은 최근 10개, 사용자 매장은 최대 50개를 브라우저 저장소에 보관합니다. 사용자 매장은 업종을 지정하면 같은 이름을 다음 검색부터 그 업종으로 해석합니다.
- 혜택 차이가 300원 이하 또는 결제금액의 1% 이하이고, 다른 카드가 목표 실적 미달이면 “실적도 함께 볼까요?” 보조 의견을 표시합니다. 최대 혜택 카드의 순위는 바꾸지 않습니다.
- 월 한도·횟수 사용량은 카드사 앱과 자동 연동하지 않으므로 “최대”로 표현합니다. 카드 상세의 공식 링크와 카드사 앱에서 실제 잔여한도를 확인하세요.

## 검증

`npm test`는 기존 저장/이월과 새 혜택 계산·갱신 실패를 검사합니다. `npm run preview` 실행 후 `npm run test:browser`로 기존 기능, 상품 연결, 금액 입력, 전월 0원, 사용자 메모 보존, 320/390/430px 레이아웃, 오프라인을 검사합니다. 브라우저가 없으면 `npx playwright install chromium`을 실행하거나 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 설치된 Chromium 경로를 지정하세요.
